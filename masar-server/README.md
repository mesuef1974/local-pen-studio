# خادم مسار (متعدد المستخدمين) — المرحلة 1 وجزء من المرحلة 2

حسابات المعلمين والمشرف، الدخول والخروج، وسجل التدقيق، والمشاريع وملفاتها، وصفحة «مشاريعي». يعمل على الجهاز نفسه وحده (قرار المالك 2026-11-28؛ النشر لاحقًا ولم يحن وقته)، واستوديو المستخدم الواحد على 8770 يعمل دونه. التصميم في [الوثيقة](../docs/masar-review-and-design-ar.html).

## الإعداد (مرة واحدة)

الأوامر من مجلد `masar-server` في PowerShell.

```powershell
py -3.12 -m venv .venv-server
```
```powershell
.\.venv-server\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
```

تشغيل خدمة قاعدة البيانات (في PowerShell بصلاحية المسؤول):

```powershell
Start-Service postgresql-x64-17
```

إنشاء الدور والقاعدة وملف `.env` والجداول. كلمات المرور تُكتب في مطالبات مخفية:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-db.ps1
```

أول حساب مشرف (كلمة المرور: 10 أحرف على الأقل):

```powershell
.\.venv-server\Scripts\python.exe manage.py create_supervisor boss "اسم المشرف"
```

بعد كل تحديث يضيف جداول (ومنه المشاريع):

```powershell
.\.venv-server\Scripts\python.exe manage.py migrate
```

## الواجهة

صفحة `/projects` على الاستوديو نفسه (`http://127.0.0.1:8770/projects`): دخول، وتغيير كلمة المرور، وإنشاء المشاريع وتغيير أسمائها وحذفها. يمرّر الاستوديو `/api/auth` و`users` و`audit` و`projects` و`assets` إلى `127.0.0.1:8780` (قرار المالك 2026-11-28)، فيبقى الأصل واحدًا ويبقى ما حفظه المتصفح على 8770. المنفذ الآخر يُضبط بـ`MASAR_UPSTREAM_PORT`. تشغيل الصفحة يلزمه: خدمة PostgreSQL، وخادم مسار على 8780، وإعادة تشغيل الاستوديو بعد التحديث. وللدخول عبر HTTP المحلي أضف `MASAR_INSECURE_COOKIES=1` إلى `.env`.

## لوحة Django

`http://127.0.0.1:8780/admin/` للمشرف، للقراءة فقط (طلب المالك 2026-11-28): الحسابات وسجل التدقيق، ومشاريع المشرف وملفاته وحده. التعديل يبقى في الواجهة البرمجية حتى لا تُتجاوز قواعد الخدمات والتدقيق. الدخول فيها يخضع لحد المحاولات ويُسجَّل. يلزمها `manage.py migrate` مرة واحدة.

## التشغيل المحلي والاختبارات

خادم التطوير على الجهاز نفسه فقط. الكعكات `Secure`، فللتجربة عبر HTTP أضف `MASAR_INSECURE_COOKIES=1` إلى `.env`.

```powershell
.\.venv-server\Scripts\python.exe manage.py runserver 127.0.0.1:8780
```

الاختبارات دون خادم قاعدة (SQLite في الذاكرة، ويُتخطى اختبار مشغّل PostgreSQL):

```powershell
$env:MASAR_DB='sqlite'; $env:MASAR_SECRET_KEY='test-only'; .\.venv-server\Scripts\python.exe manage.py test; Remove-Item Env:MASAR_DB, Env:MASAR_SECRET_KEY
```

وفي CI تعمل الاختبارات على PostgreSQL 17.

## الواجهة البرمجية

كل الطلبات `POST` تحتاج ترويسة `X-CSRFToken` من `GET /api/auth/csrf`.

| المسار | من |
|---|---|
| `GET /api/auth/csrf` و`POST /api/auth/login` | أي زائر |
| `GET /api/auth/me` و`POST /api/auth/logout` و`POST /api/auth/change-password` | صاحب جلسة |
| `GET` و`POST /api/users` و`POST /api/users/{id}/disable` و`enable` و`reset-password` | المشرف |
| `GET /api/audit` | المشرف |
| `GET` و`POST /api/projects` و`GET /api/projects/{id}` و`POST /api/projects/{id}/rename` و`state` و`delete` | صاحب المشروع وحده |
| `POST /api/assets` (بايتات الصورة) و`GET /api/assets/{sha256}` | صاحب الملف وحده |

حالة المشروع: `{"revision": n, "state": {...}}`، والصور فيها مراجع `asset:<sha256>` لا بيانات مضمَّنة. الرقم القديم يُرفض بالرمز 409، وإعادة الإرسال نفسها لا تغيّر شيئًا. `client_key` عند الإنشاء يمنع تكرار المشروع. الملفات في `var/files` (أو `MASAR_FILES_DIR`) خارج git، ويلزم نسخها مع القاعدة. الحد 32 ميغابايت للملف و16 للحالة.

## الضوابط وحدودها

- كلمات المرور بـArgon2، بحد أدنى 10 أحرف ورفض الشائعة. كلمة المرور المؤقتة تظهر مرة واحدة وتُغيَّر عند أول دخول.
- الجلسة تنتهي بعد 30 دقيقة خمول أو 12 ساعة، وتبطل بتغيير كلمة المرور أو تعطيل الحساب.
- 5 محاولات للحساب و20 للعنوان كل ربع ساعة. أثر ذلك أن من يعرف اسم الدخول يستطيع قفله ربع ساعة؛ إعادة ضبط المشرف لكلمة المرور تفك القفل.
- سجل التدقيق إضافة فقط: يمنع الـORM تعديله، ومشغّل في PostgreSQL يرفض التعديل والحذف. الدور `masar` يملك الجدول فيستطيع تعطيل المشغّل؛ فصل مالك الجداول عن مستخدم التشغيل عمل المرحلة 5.
- عنوان الجهاز من `REMOTE_ADDR` وحده. خلف الوسيط العكسي (المرحلة 5) يجب تمرير العنوان الحقيقي وإلا صار حد العنوان مشتركًا بين الجميع.
- المشرف لا يرى مشاريع غيره. الحذف إخفاء فقط: لا استرجاع ولا محو نهائي للصفوف والملفات بعد، ولا حصة تخزين.
- قبل النشر: حصة تخزين لكل حساب، وحد لحجم الجسم في الوسيط العكسي، وخادم إنتاج بدل `runserver`.
- لم يُبنَ: إدارة الحسابات في الواجهة، وفتح المشروع في الاستوديو وربط الاستوديو بدل IndexedDB، واستيراد العمل الحالي، وحذف الجلسات المنتهية دوريًّا (`manage.py clearsessions`)، ومدة احتفاظ سجل التدقيق.
