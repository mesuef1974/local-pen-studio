# ذاكرة المشروع المشتركة

مرجع سريع للأدوار والاتفاقات المستقرة؛ قرار المالك الأحدث هو الحاكم. **آخر تحديث: 29 أكتوبر 2026.** اقرأه عند تنسيق البطاقات أو آراء الجلسات، ولا تفترض أن نسخة كل فرع محدثة.

## مهام الجلسات داخل الفلو

| الجلسة | متى تُسند إليها البطاقة | مسؤوليتها ومخرجها في الفلو |
|---|---|---|
| **عصف ذهني** | التنسيق، التقارير، التوصيات، أو بطاقة لا يملكها اختصاص آخر | يحدد نطاق البطاقة من أمر المالك، يجمع الآراء عند طلبها ويسجلها في السجل المشترك، ثم يودع التقرير أو المخرج وأدلته في البطاقة. لا ينسب رأيًا أو اعتمادًا دون سجل. |
| **ليزر** | العتاد الليزري، توافق المواد والعمليات، السلامة، البرامج ومصادرها | ينجز المراجعة الفنية المسندة، ويفصل المعلومة الموثقة عن الاستنتاج، ويسجل المصادر والقيود والنتيجة وأدلة الفحص في البطاقة. |
| **مسار القلم** | هندسة المسارات وتطويرها وقياساتها | ينتج أو يراجع المسارات ضمن نطاق البطاقة، ويسجل وحدات القياس وطريقتها والعينات والنتائج وأدلة التحقق. |
| **تنسيق إنتاج SVG** | عقد SVG والتحقق من التحويل والتصدير | يطبق عقد SVG المسند، ويتحقق من سلامة التحويل والتصدير، ويسجل الملفات والنتائج والأدلة والفجوات في البطاقة. |
| **جلسة جديدة** | بعد أن يضيفها المالك إلى الجلسات النشطة ويحدد اختصاصها | يضاف لها صف باسمها واختصاصها ومخرجها المتوقع ومعايير التحقق المناسبة. لا تُسند لها بطاقة قبل تعريف هذه الحدود؛ وبعدها تتبع الفلو المشترك نفسه. |

**مسؤولية مشتركة لكل جلسة مستلمة:** تبدأ البطاقة وتحدّث حالتها وسجلها في قاعدة المصنع، تنفذ نطاقها على فرع المهمة، وتجري الفحوص المطلوبة، ثم تدفع فرعها وتسجل SHA والملفات والملخص وأدلة التسليم. عامل التكامل يتولى PR وفحوص GitHub والدمج ومزامنة `main`؛ لا تنقل الجلسة بطاقتها مباشرة إلى الاكتمال قبل توثيق نتيجة التكامل في المصنع. المالك يصدر الأمر ويختار الجلسة وصاحب القرار النهائي، وليس منفذًا بديلًا عن الجلسة المسندة.

## الفلو ببساطة

1. المالك يصدر الأمر ويختار الجلسة؛ البطاقة والإسناد وطابور التنفيذ تحفظها قاعدة المصنع.
2. الجلسة تنفذ على فرع المهمة، وتسجل البدء أو العائق في سجل البطاقة.
3. الجلسة تدفع فرع المهمة إلى `origin`، ثم تسجل SHA والمسارات وملخص التسليم عبر API المصنع.
4. الجلسة تسجل نتائج معايير البطاقة وأدلتها؛ النجاح ينقل البطاقة إلى التحقق ويضع تكامل Git في طابور قاعدة البيانات.
5. عامل المنسق ينشئ/يتابع PR، ويتحقق من SHA والمسارات وفحوص GitHub. ينتظر المراجعة إذا طلبها GitHub، ولا يتجاوز الفحوص أو التعارضات.
6. بعد استيفاء الشروط يدمج العامل PR إلى `main` ويزامن نسخة `main` المحلية بالتقديم السريع فقط. تكتمل البطاقة بعد تطابق `main` المحلي و`origin/main` وتُحفظ كل الحالات والأدلة في تاريخ البطاقة.
7. لا ترسل الجلسات رسائل تنسيق لبعضها؛ قاعدة المصنع وخطها التاريخي هما سجل التشغيل والتسليم. بطاقات المراجعة التي لا تتطلب تغييرات كود تسجل تقريرها وأدلتها في المصنع.

## قواعد سريعة

- الآراء استشارية؛ سجّل «لم يرد» عند غياب الرد، واحفظ آراء الجلسات وملخص التوصيات في سجل مركزي بدل ملفات منفصلة.
- اعتمد المالك ذاكرة مشروع مشتركة واحدة؛ لا تنشئ ذاكرة دائمة منفصلة لكل جلسة. تبقى تقارير الجلسات مراجع مرتبطة بمواضيعها.
- حافظ على ملكية الفروع. عامل التكامل وحده يدمج PR بعد اجتياز الشروط، ولا يتجاوز التغييرات المحلية أو يحذف الملفات عند تعذر المزامنة.
- قائمة الجلسات النشطة وحالة البطاقات مصدرها قاعدة المصنع الحية.
