# اعتماد الإصدارات والنشر

## سياسة الإصدار

- `main` مصدر الإصدارات المعتمدة، وأرقامها `vMAJOR.MINOR.PATCH`؛ ما قبل الاستقرار يبدأ بـ`v0.x.y`.
- الإصلاح المتوافق يزيد PATCH، والإضافة المتوافقة تزيد MINOR، والكسر المقصود يزيد MAJOR.
- كل إصدار مرتبط بمعرّف commit محدد اجتاز Quality gate على main، مع سجل التغييرات والحدود المعروفة.
- استخدم `.github/release.yml` لتجميع ملاحظات GitHub. لا تنقل وسم إصدار قائم؛ أنشئ إصدارًا جديدًا.
- يظل الإصدار Draft حتى اكتمال القائمة وموافقة المالك. لا ينشئ CI إصدارًا أو ينشر التطبيق.

## قائمة الاعتماد

- [ ] نجاح Quality gate على commit الإصدار نفسه، وفحص الأسرار والتبعيات المتغيرة.
- [ ] تجربة Windows فعلية: تشغيل، استيراد، تحرير، اعتماد، استخراج، محاكاة وتصدير SVG/JSON.
- [ ] إذا تأثرت المعالجة: اختبار FLUX وBiRefNet الحقيقيين بالتناوب مع دليل الجهاز والبيئة والزمن.
- [ ] مطابقة CairoSVG محليًا على Windows؛ لا تعتبر نجاح Linux إثباتًا لتوافق DLL/CUDA.
- [ ] تثبيت إصدارات الاعتماديات الفعلية وتسجيل مراجعات النماذج وبصماتها وتراخيصها دون تضمين الأوزان.
- [ ] توثيق نطاق الاختبار وما لم يُختبر وخطوات الإعداد والترقية والرجوع.
- [ ] التأكد من خلو المرفقات من صور المستخدمين والأسرار والبيئات والأوزان.
- [ ] موافقة صريحة قبل نشر الإصدار أو تحديث الخدمة.

## النشر والرجوع

التطبيق محلي حاليًا. الدفع إلى GitHub أو دمج طلب لا يحدثان الخدمة ولا يشغلان تنزيل نماذج.
عند تفويض النشر: جهّز حزمة من commit معتمد، احسب SHA-256 واحتفظ بها، اختبرها في
مجلد منفصل، ثم انقل الحزمة نفسها بعد الموافقة. احتفظ بالحزمة السابقة وإعداداتها الآمنة.
تحقق من `processing` قبل إعادة تشغيل عملية الخادم المملوكة للتطبيق فقط، ثم افحص
صحة الخدمة والاستيراد والتصدير والسجلات دون طباعة بيانات حساسة.
عند الفشل استعد الحزمة السابقة، وافحص الصحة، ووثّق السبب. أي تغييرات بيانات مستقبلية
تحتاج خطة نسخ احتياطي واسترجاع مستقلة.

لم تُجهّز استضافة أو أسرار نشر أو صلاحية كتابة للإصدارات في CI. عند اعتماد استضافة
مستقبلًا تُفصل بيئة التجربة عن الإنتاج، وتُحدد الموافقات والصلاحيات حسب خطة GitHub.

## الإعدادات القابلة للمراجعة

`.github/main-ruleset.json` و`.github/release-tags-ruleset.json` نسختان للإعدادات المقصودة.
وجود الملف وحده لا يفعّل حماية GitHub؛ يجب مطابقة قواعد الخادم معها بعد أي تعديل.
