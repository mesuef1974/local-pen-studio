# استمرارية مسار العمل 0001 — الاختبار أولًا

## النطاق الحالي

ملف الاشتراك `.codex/handoff.json` يفعّل **المراقبة فقط** بعتبة 200000 توكن.
البطاقة `docs/handoffs/HANDOFF0001.md` للمعنى وحالة المهمة؛ بيانات Git والملكية والقياس
تُكتب محليًا في المسار الناتج عن `git rev-parse --git-path handoff/0001` ولا تُدفع إلى GitHub.
لا يكتب السكربت متن البطاقة؛ يلخصه المساعد، ويتحقق السكربت من اكتماله وحداثته.

**لا يوجد في هذا الإصدار موصل لإنشاء جلسة فعلية أو أرشفتها.** تُختبر دورة النقل عبر
واجهة نقل في الذاكرة، ولا يُسمح بتمرير موصل حي حتى لو اكتملت الشروط. كذلك لا يوجد
مسح للسياق أو نشر أو جدولة أو git commit/push أو إغلاق عملية. تفعيل النقل الحقيقي
مرحلة مستقلة بعد موافقة المستخدم واختبار ربط التطبيق واستلامه.

## مصدر القياس

حدث الخطاف لا يتضمن عداد `/status` مباشرة. المحول `bounded-jsonl-token-count-v1` يقرأ
أحداث `token_count` فقط من آخر 1 MiB من سجل الجلسة، ويتحقق من معرّفها في أول سطر.
لا يقرأ تاريخ الرسائل كاملًا ولا يسجل نصوص المستخدم أو الأوامر أو مخرجات الأدوات.
يعامل `last_token_usage.total_tokens` كتقدير ضغط السياق، وليس كمجموع الاستهلاك.
يحتفظ منفصلًا بالعداد التراكمي والمدخلات المخزنة والمخرجات والتفكير؛ الكاش جزء من
المدخلات والتفكير جزء من المخرجات، ولا يُجمعان مرتين. يلزم اختبار معايرة مع شاشة
`/status` قبل الاعتماد على تطابق العدد المعروض حرفيًا.

صيغة السجل ليست واجهة Codex مستقرة. غياب القياس أو فساده أو اختلاف الجلسة أو تقادمه
أكثر من 300 ثانية يمنع الجاهزية. حدث الضغط يلغي القياس ونقطة التحقق السابقة؛ لا تستمر
الآلية استنادًا إلى ضغط سياق سبق اختصاره. تحفظ آخر 1000 عينة رقمية في `usage-history.json`
لتسهيل المقارنة لاحقًا، دون استنتاج توفير أو كلفة أسبوعية غير مقاسين.

## شروط التسليم

بلوغ العتبة يجهز تقريرًا فقط، ولا يقاطع الدور. يتطلب تقييم الجاهزية جميع ما يأتي:

- أحدث قياس معروف للجلسة المالكة يبلغ العتبة.
- وصول `Stop` دون أدوات أو وكلاء فرعيين نشطين أو أحداث مجهولة الهوية.
- اكتمال الأقسام الثمانية وبيانات البطاقة، وحالتها `ready_to_resume`، وعدم وجود عمليات معلقة.
- نقطة تحقق تربط بصمة البطاقة وبصمة المحتوى المعدل والفرع وHEAD بالمالك نفسه.
- عدم وجود قفل فهرس Git أو دمج أو rebase أو cherry-pick جارٍ.
- استجابة صريحة `processing=false` من خدمة FLUX المحلية. تعذر الاتصال يعني مجهولًا ويمنع الجاهزية.

عند `Stop` تحفظ نقطة تحقق تلقائيًا فقط إذا حدث تحديث فعلي لبطاقة مكتملة جاهزة وفي
نقطة آمنة. تغيير الملفات لاحقًا يبطلها. تستثنى البطاقة من بصمة مساحة العمل، وتُفحص
بصمتها على حدة لمنع الحلقة الذاتية. لا يلزم إيداع التعديلات المعلقة أو حذفها.
حالة `waiting_user` أو `completed` لا تنشئ عملًا جديدًا ولو تجاوز السياق العتبة.

الخطافات لا ترى كل برنامج أو عملية خارجية على الجهاز. قائمة العمليات المعلقة في
البطاقة، ودليل التحقق، ومراجعة الجلسة المستلمة أجزاء لازمة؛ الفحص ليس ضمانًا لخمول
كل برامج GPU أو العمليات المستقلة. عملية غير معروفة تمنع التسليم إلى حين التحقق منها.

## الملكية والحفظ

يربط المثبت UUID جلسة Codex بالرقم 0001 محليًا. أي جلسة أخرى تُهمل، ولا تستلم البطاقة
تلقائيًا ولا يمكنها تغيير الملكية. القفل حصري لكل نسخة عمل، والكتابات JSON ذرية.
أي خطأ يُسجل بنوعه فقط، دون بيانات حساسة. الخطاف يخرج دون إسقاط الجلسة، لكن الخطأ
لا يمنح أهلية انتقال. القفل المتبقي بعد تعطل عملية لا يُحذف تلقائيًا؛ يلزم التحقق
من انتهاء العملية المالكة قبل إزالته.

عقد النقل المختبر في الذاكرة: معرّف محاولة ثابت، إنشاء مستقبل مرة واحدة، استلام
بطاقة مع بصمة، تأكيد تطابق مساحة العمل، نقل ملكية الكاتب، ثم أرشفة المصدر. غياب
التأكيد أو تغير الملفات يبقي المصدر مالكًا؛ فشل الأرشفة بعد النقل لا يعيد ملكية
الكتابة إلى القديم، وتُعاد المحاولة دون إنشاء مستقبل مكرر. لا يعرض التقرير هذا
العقد باعتباره انتقالًا حقيقيًا.

## تسجيل الخطافات

من جذر المشروع، وفي جلسة Codex المراد ربطها:

```powershell
python scripts/install_handoff_hooks.py --root .
```

يستخدم المثبت `CODEX_THREAD_ID` أو معرّفًا صريحًا عبر `--session`. يضيف تعريفاته إلى
`~/.codex/hooks.json` مع الحفاظ على الموجود، ويأخذ نسخة احتياطية محلية قبل التعديل.
إعادة تشغيله لا تضيف نسخًا مكررة، ويرفض الاستيلاء على بطاقة جلسة أخرى.
لا يعدّل config.toml ولا يضبط الثقة ولا يستخدم تجاوزًا لثقة الخطافات.

**يجب مراجعة التعريفات ومنحها الثقة في Codex قبل تشغيلها تلقائيًا.** في CLI يمكن
استخدام `/hooks`. دعم الأحداث ووصولها في تطبيق سطح المكتب يحتاج اختبارًا بعد الثقة؛
اختبار عقد JSON مباشرة لا يثبت وصول الأحداث آليًا من التطبيق.
مصدر هذا الشرط: [توثيق Codex للخطافات](https://learn.chatgpt.com/docs/hooks).

## التحقق والأوامر

```powershell
python scripts/test_handoff.py
python scripts/handoff.py status --root .
```

لأخذ عينة يدوية آمنة دون توليد حدث توقف أو بدء جلسة:

```powershell
python scripts/handoff.py sample --root . --transcript "مسار سجل الجلسة المالكة.jsonl"
```

تقرأ العينة القياس فقط ولا تزعم أن الدور انتهى. الملفات المحلية `report.json` و
`snapshot.json` و`state.json` تعرض أسباب المنع والحالة، ولا تمثل تفويضًا للتنفيذ.
الاختبارات تستخدم مستودعات مؤقتة وخطافات اصطناعية ونقلًا في الذاكرة. تعمل على Windows
وLinux في CI، ولا تنشئ محادثة أو تؤرشف هذه الجلسة.

للإيقاف، اجعل `enabled=false` في ملف الاشتراك. يحتفظ ذلك بالبطاقة والحالة والنسخ
الاحتياطية، ويجعل السكربت يتجاهل أحداث هذا المشروع. تعطيل تعريفاته من متصفح الخطافات
متاح كذلك؛ لا تحذف تعريفات المستخدم الأخرى.
